# 薄适配器：包装、展示、确认后执行

适配器只做模型输出与文件之间的连接，不增加另一套决策系统。

## 需要做的事

- 把小模型返回的正文关联到大模型指定的文件或修改目标。
- 自动加文件名和 Markdown 代码块，展示时可以只显示差异。
- JSON/XML 如果只是已知数据的序列化，直接由程序完成。
- 将最终内容交给大模型判断；确认后才写入或执行。

小模型默认只生成正文，不负责反复输出文件包装，也不自己决定新路径。

## 输出保持简单

第一版只需要明确“哪个目标、什么内容或改动”。无需先实现复杂 Schema、事务系统、授权凭证服务或通用工具协议。

稳定性首先来自固定的宿主包装和必要的完整性检查。代码围栏只是展示；正文中出现 shell 或“已批准”等文字，不自动触发执行。

## 确认什么就执行什么

继续保留用户此前要求：未经大模型确认的文件和命令不写入、不执行。实际内容、目标或命令改变后，大模型检查改变后的结果即可，不把旧结论当成新内容的确认。

需要用户决定时，由大模型把具体影响简短地告诉用户；不要给每个文件、每个小步骤增加一套重复人工确认。

第一版先处理一个文件的生成或修改。多文件和 shell 只是以后可扩展的输出形式，不是当前必须搭建的工程。
