# 本地怎么开始

可以在当前 Mac 上先验证这个想法。已有硬件记录为 **M1 Pro、16 GB 统一内存**；第一步只运行现成小模型，让它接收大模型的简短指令并返回代码正文。本文仅说明后续做法，当前没有安装、下载、运行模型或测量速度。

## 首选组合

采用 **MLX-LM + Qwen2.5-Coder-1.5B-Instruct 的 4-bit 量化版本**作为本机候选。MLX-LM 面向 Apple Silicon，支持推理、量化和 LoRA；Qwen 已有基础代码能力，不需要从零教语法。这是便于开始的选择，兼容性、内存和速度仍需本机验证。

## 最小操作顺序

1. 后续实现者准备独立运行环境，取得来源明确的模型与量化配置。
2. 先选几个现有项目里的小修改，由大模型说明改哪里、怎么改，并给出必要原文。
3. 小模型只返回修改后的正文，不聊天，不说明理由，不决定业务方案。
4. 大模型看结果是否符合自己的指令，向用户给出简短、可决策的结论。
5. 只有在大模型审批通过后，适配器才写入文件或执行命令。

初期一次处理一个函数或一个明确修改范围即可。文件名、代码围栏等固定包装交给适配器，避免小模型重复输出。推理跑通后让模型常驻，减少每次重新加载的等待。

## 本机先做到什么程度

先看同一批任务是否生成正确、等待是否更短，再决定是否继续。记录几次完整任务的耗时，区分首次加载和常驻后的请求；不要只看每秒 token 数。大模型可以沿用用户已有的服务，小模型在本机运行，不要求两者同时装进这台 Mac。

16 GB 是整个系统共享的内存，先使用短输入、短输出。第一版无需训练平台、云 GPU 或扩散环境。普通 SFT 仅为日后可选项，见[训练与扩散](05-training-and-diffusion.md)。
