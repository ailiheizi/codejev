# 只准备正常的指令与结果配对

数据只服务一个目标：**大模型用少量明确的话告诉小模型怎么做、怎么改，小模型直接返回正确结果。** 先用现成模型，不必先建设数据集；将来需要普通 SFT 时，再整理这些正常配对。

## 一条样本只表达一件事

输入是“简短指令＋必要原文”，输出是“正确结果”。新建内容时给出必要的类型、字段和调用方式；修改内容时给出相关原文，说明修改位置与动作即可。函数名、变量名、字段、条件等已有决定直接由大模型提供。

例如，指令可以是：“保留其余内容，把这个函数改为只返回 active 为 true 的用户。”输入再附相关函数，目标就是修改后的函数正文。不要求小模型解释、不需要推理过程，也不另造一套复杂语言。

“最少的话”以能明确执行为准。已有原文能表达的信息不重复说；缺少的决定由大模型补齐，不交给小模型重新设计。

## 从哪里取

优先使用用户已有项目中熟悉、正确的函数和正常修改记录；也可以让大模型根据明确指令提供正确结果，核对后使用。公开项目仅作补充，挑选与目标任务有关且来源、许可证明确的内容。参考已有[代码资产记录](reference-notes/code-corpus.md)，不需要先抓取大量仓库。

整理时只留下指令、必要原文、正确结果和简单来源说明。先覆盖常见的新增函数、改字段、改条件、改调用方式，以及 JSON 内容变换；遇到实际需求再增加种类。训练用例之外保留几条正常任务，看看换个名字或组合还能否照做即可。

## 不增加学习分支

不收集失败样本，不做错误分析、修复回流、负样本训练或强化学习。日常修改请求是用户要求改变原文，与根据模型失败建立学习循环是两件事。结果不符合要求时由大模型继续给明确指令，不自动转成训练材料。

未来若做普通 SFT，只把确认正确的配对转成训练工具接受的格式。无需数据平台、复杂分组体系或额外评审角色。
