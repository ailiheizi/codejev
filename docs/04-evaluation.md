# 简单看看是否好用

目的只有一个：大模型少说话，小模型快产出，大模型再给用户一个简短、可决策的结论。先观察这条交互是否顺畅，不建设专门的评测平台，也不做错误学习。

## 选几个日常任务

从当前项目挑几个熟悉的小改动，例如新增字段、修改条件、调整返回结构、根据已有接口补一个函数。给出相关代码，由大模型直接说明改哪里、怎么改；不要先让大模型写完整答案再压缩成指令。

小模型按指令返回修改结果，大模型判断是否满足要求。用户只需要看到完成了什么，以及仍需自己决定的事项。未获大模型确认的文件和命令不执行；只有用户需要决定的地方才呈现选项，不为每个文件新增人工确认。

## 只看三件事

- 是否按指令完成：字段、条件和修改位置符合大模型要求。
- 输出是否可用：代码或 JSON 可以使用；必要时利用项目已有检查。
- 完整交互是否更快：从收到需求，到大模型给出用户可决策的结论，连同等待和检查一起观察。

让大模型直接完成同样几个任务，做一次简单对照即可。记下指令、结果、整体耗时和使用感受，不要求复杂报表。

如果拆分后更顺手、更快，就继续使用；如果需要来回解释或整体更慢，就简化指令或换个更适合的小任务。少量观察只帮助决定下一步，不能据此宣称通用性能优势。后续顺序见[最短流程](08-roadmap.md)。
