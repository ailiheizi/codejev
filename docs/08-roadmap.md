# 最短流程：说清楚、快产出、给结论

核心想法是“用最少的话做最多的事”。大模型负责思考怎么做、怎么改；小模型迅速把指令展开成代码或结构化内容，再交回大模型判断。用户得到简短结论，只处理需要自己决定的事项。本文只约定想法和顺序，不包含实现代码或训练任务。

## 1. 形成最短指令习惯

从项目里一个常见改动开始。大模型提供目标位置、具体动作、字段或变量、必要条件和相关原文，省掉背景复述与推理过程。不强制复杂 DSL，也不要求为所有任务填写长表。简短的前提是交代清楚，不能让小模型补猜业务决策。

## 2. 让已有小模型直接响应

先用现有小代码模型，本地可从 MLX-LM 配合量化小模型尝试，选择参考[本地方案](02-local-setup.md)。小模型只返回要求的正文或修改片段，不聊天、不规划、不承担 agent 工作。文件包装交给简单适配器。

## 3. 大模型给用户结论

大模型看返回结果，给出完成情况和必要选项。未获大模型确认的文件和命令不执行；只有用户需要决定的地方才呈现选项，不为每个文件新增人工确认。按[简单观察方法](04-evaluation.md)看看是否好用、完整交互是否更快。

## 4. 有需要再选加速办法

现有模型好用就先用。需要更稳定地遵守指令时，可选普通 SFT，用“短指令 → 正确输出”的配对样本训练，不做错误学习或自动回流。只有实际生成速度仍不够时，再考虑扩散模型。这两项都是后续选项，不是前面流程的前提，也不扩展成复杂工程。
