# 给后续模型：按这个简化想法接手

## 用户最新要求

> 不做错误学习，不做太复杂的。大模型告诉小模型怎么做、怎么改；用最少的话做最多的事。小模型快速给大模型可判断的结果，大模型快速给用户可决策的内容。

这段是整理后的原意。用户当前只要想法与参考文档，明确没有要求本轮写实现代码。后续任务以用户当时的授权为准。

## 只保留这条主线

用户需求 → 大模型短指令 → 小模型产出 → 大模型判断与简短建议 → 用户在需要时作决定。

适配器负责文件对应、固定格式和确认后执行。保留此前要求：文件或命令未经大模型确认不能写入或执行；不要借此扩展成多级人工审批系统。

## 角色不要混

- 大模型决定做法、修改范围、字段和变量；结果回来后决定是否采用及如何告诉用户。
- 小模型只接收明确指令和必要原文，返回代码、改动或结构化结果。不负责业务分析、规划、解释、错误学习和自我改进。
- 用户只看到必要结论和真正需要选择的事项，详细代码可以展开查看。

“小模型不用懂”按职责理解：不安排业务决策任务，直接使用已有代码能力完成指令。不需要围绕这句话另开一套能力研究。

## 接手时不要加回这些

不做错误学习、失败回收训练、强化学习、自动修复闭环、复杂 agent 编排、巨大 DSL、检索平台、统计评测工程或授权凭证平台。此前较复杂的建议已被本版替代。

普通 SFT 可以是以后可选的固定指令与标准输出训练，不等于错误学习。当前任务不要求训练；扩散也只是加速参考。

## 推荐起点

先用现有小代码模型处理明确的局部修改：大模型给必要原文和一句够用的改法，小模型返回结果，大模型给用户短结论。需要调整时，由大模型重新发指令即可。

本机为 M1 Pro、16GB 统一内存。可参考 MLX-LM 与 Qwen2.5-Coder-1.5B-Instruct 量化版本；这是候选建议，没有实测运行速度。语言、底座和训练安排都不是已经锁定的用户要求。

## 参考怎么融合

- jev：借明确问题和短回答。
- Loom：借决定与文件产出分离。
- Fast Apply：借原文加改法、快速返回修改结果。
- selector：已有候选时可以选，不必先搭检索层。
- Dream-Coder、Fast-dLLM：以后需要更快输出时再看。

事实出处与限制保留在[参考目录](07-references.md)和[代码资产笔记](reference-notes/code-corpus.md)。参考中有复杂机制，不表示本项目要采用。

## 最短阅读路径

先读[核心想法](00-core-idea.md)与[收敛方案](09-synthesis-and-decisions.md)，再按需读[本地方案](02-local-setup.md)、[薄适配器](06-artifact-protocol.md)和[简单验证](04-evaluation.md)。

后续只需证明：小模型按指令产出的结果可用，这条交接比大模型直接做更省时间或更省输出。先用少量真实任务观察，不为证明想法先造一个大系统。
